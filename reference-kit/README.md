# 일정·작업·인수인계 레퍼런스 키트

회사에 이미 있는 웹사이트와 DB를 유지하면서 필요한 기능만 옮겨 쓰는 예제다. 전체 사이트 재구축이나 DB 교체를 전제하지 않는다. 실제 메일함·사내 DB 연결, 직원 정보와 평가 값은 포함하지 않는다.

실행 후 `/reference-lab/`에서 가짜 인원·업무로 확인한다. `/home-designs/`는 디자인 선택 대상인 홈화면 16안, `/schedule-designs/`는 이전 일정 화면 16안, `/design-lab/`은 이전 8개 디자인 비교이며 배정 기능과 독립되어 있다.

## 포함한 기능

1. 메일 본문의 지정된 필드에서 업무 추출, CSV·XLSX의 열 검증·미리보기.
2. 예정일과 미완료 여부로 오늘 할 일을 필터링하고 카드로 표시.
3. 역량 적격성·가중치·하루 용량으로 배정 초안 생성.
4. 근무 구간·점심/휴게·사람 일정·설비 일정·마감 충돌 검사.
5. 배정 이유·인원별 작업량·미배정 사유 표시.
6. 검토 후 한 번의 변경으로 확정 일정과 설비별 체크리스트 생성. 설비 전용 → 역량 공통 → 기본 항목 순으로 선택하고 생성 시 템플릿 내용을 복사해 고정.
7. 항목별 결과·메모·작업 이력 저장.
8. 필수 항목 완료 후 인폼 자동 생성, 반복 완료해도 중복 인폼 없음.
9. 인폼이 없어도 볼 수 있는 설비 이력.
10. 날짜별 미완료·완료·부분 체크 인수인계 요약과 브라우저 인쇄.
11. 담당자 역량·가중치·용량 변경, 버전 충돌 방지.
12. 날짜별 메모·설비 링크·역방향 메모 조회와 Markdown 출력.
13. 담당자·날짜·시간 직접 지정과 변경, 진행 체크 보존·충돌 검사.
14. 가짜 예제 공간 초기화. 본 포털 데이터는 건드리지 않고 이전 레퍼런스 버전은 서버 이력에 보존.

## 배정 규칙

고정된 로컬 규칙으로 동작하며 AI나 외부 API를 호출하지 않는다. 배정은 우선순위 높은 업무 → 마감 빠른 업무 → 높은 필요 역량 순으로 진행한다.

1. 필요 역량을 충족하고 활성 상태인 담당자만 후보로 둔다.
2. 하루 용량을 넘거나 근무·휴게·기존 일정·설비 중복·마감 조건을 만족하지 못하면 후보에서 제외한다.
3. 후보 점수는 `현재 배정 분 / (하루 용량 × 가중치) + 초과 역량 수준 × 0.03`이다. 낮은 점수가 우선이며 동점이면 빠른 시간, 담당자 ID 순으로 고른다.
4. 가중치가 커도 시간·용량·역량 제한을 무시하지 않는다.
5. 맞는 후보가 없으면 배정하지 않고 사유를 돌려준다.

이는 설명 가능한 탐욕적 배정 예제이며 전역 최적 해법이나 실제 직원 역량 평가가 아니다. 가중치 의미, 역량 단계, 긴급 업무·연속 작업·이동·준비 시간·교대·휴가·법정 근무 규칙은 회사 업무 기준으로 정의해야 한다. 현재 이동·준비·선행 작업 의존성·분할 작업·여러 명 동시 투입·자정을 넘는 교대는 처리하지 않는다. 빈 시간 탐색은 5분 간격이고 화면 예시는 09:00–17:00이다. 일정 직접 지정·이동 UI는 제공하지만 취소·반복·드래그 이동은 아직 없다.

## 저장·원자성·권한

예제는 기존 store의 `ref:workspace` 한 레코드를 버전 관리해 전체 흐름을 원자적으로 저장한다. 함수는 변경 전 복사본에 적용하므로 검증 실패 시 저장하지 않는다. 운영에서는 업무·담당자·일정·체크·인폼·이력을 회사 DB의 별도 테이블과 트랜잭션으로 옮기는 것을 권장한다. 체크 완료·인폼 생성은 동일 트랜잭션, 인폼은 source_task_id 유일 제약을 유지한다.

모든 API는 기존 인증·CSRF를 통과한다. 레퍼런스 쓰기는 데모 모드에서만 가능하며 production에서는 403으로 차단한다. 회사에 옮길 때 과장급의 배정 확정·가중치 수정 권한과 담당자의 작업 기록 권한을 실제 사내 로그인에 맞춰 연결한다. 브라우저의 사용자명·역량 값을 신뢰해 권한을 부여하지 않는다.

## 가져오기 규약

엑셀·CSV 첫 시트 필수 열: `작업명, 설비, 예정일, 예상분, 역량, 필요레벨, 우선순위`. 선택 열: `시작가능, 마감`. 예정일은 YYYY-MM-DD, 시각은 HH:mm, 필요레벨·우선순위는 1~5다. 파일은 최대 5MB이지만 업무 레퍼런스는 2,000행까지 허용한다. 원본 파싱의 ZIP·매크로·외부 참조 제한도 유지한다.

메일은 본문에 `작업:`, `설비:`, `예정일:`, `예상분:`, `역량:`, `필요레벨:`, `우선순위:`를 넣는다. 여러 업무는 `---`로 구분한다. 임의 문장 의미를 추측하지 않는다. 실제 메일 서버의 인증·검색·첨부파일 조회는 미구현이며 사내의 승인된 연결 어댑터가 이 정규화 형식으로 전달해야 한다.

원천에서 준 날짜·제목·설비·분량·역량·시간 조건의 해시로 재반입 중복을 제외한다. 취소·수정 메일, 변경된 작업의 기존 일정 재배정은 별도 검토 흐름으로 추가해야 한다. 제목만으로 동일 업무를 추정하지 않는다.

## 화면의 정보 분리

- 오늘 화면: 필터링한 업무 카드와 확정 일정, 담당자 부하만 우선 표시.
- 배정 초안: 추천 근거와 미배정 사유를 검토하는 별도 단계.
- 작업 상세: 선택한 업무·설비의 체크리스트와 관련 인폼만 표시.
- 설비 이력: 확인이 필요할 때 별도 화면에서 조회.
- 가중치 설정: 일상 작업 화면에서 분리.

기존 회사 화면에 모든 기능을 동시에 추가하지 말고, 현재 화면과 선택한 업무의 맥락에 따라 필요한 부분만 펼친다.

세부 인계 순서는 [recipes](recipes/)를 참고한다. 회사 파일·직원 실명·가중치·인증정보·원문 메일은 GitHub에 올리지 않는다.

장소·상세·반복 생성은 recipes/11-calendar-details-recurring.md를 참고한다. 반복 매크로는 기간 안의 업무를 미리 생성하며 코드 실행·외부 통신을 하지 않는다.

## v0.6 HTTP 연결부와 누락 없는 반입

`service-router.js`는 `/api/integration`의 읽기 전용 기본값·서버 역할·CAS 경계다. 기존 `router.js`와 recipes/01~11도 모두 포함한다. `plan-cards.js`는 배정 결과를 화면 카드로 투영한다. [12번 레시피](recipes/12-http-service-boundary.md), [API 표](../docs/INTEGRATION-API.md), [v-etch 파일 지도](../docs/VETCH-HANDOFF.md)를 읽는다. `npm run export:reference`로 DB·업로드·fixtures 파일을 제외한 릴리스 참조 폴더를 만들 수 있다.
