# 09. 날짜별 메모와 설비 연결

읽기: `workflows.js`의 saveDailyNote, router.js의 PUT /daily-note, public/reference-lab/app.js의 renderNotes·renderHistory.

입력 `{day,text,actor}`. 날짜와 최대 20,000자를 검증한다. 본문은 HTML로 실행하지 않고 원문 텍스트로 저장한다. `[[...]]` 중 현재 업무에 등록된 설비명과 정확히 일치한 것만 equipment 배열에 넣는다. URL이나 없는 설비명은 외부 링크로 전환하지 않는다. 저장 결과는 `{day,text,equipment,actor,updatedAt}`다.

데모는 workspace.dailyNotes[day]에 저장한다. 운영은 별도 daily_notes 테이블과 note_equipment 연결 테이블로 옮기고 수정 버전을 검사한다. 이 예제는 날짜당 부서 공유 메모 하나다. 개인 메모로 오해하게 만들지 않는다. 사내 사용자·부서 권한을 적용하고 작성자는 인증된 서버 값으로 정한다.

화면은 명시적 저장, 저장 전 초안 표시, 날짜·화면 이동 중 메모 초안 유지, 새로고침/닫기 전 미저장 경고, 서버 저장본 확인, Markdown 다운로드를 지원한다. 브라우저를 닫은 미저장 초안의 자동 복구는 미구현이다. 전역 workspace 충돌이 발생하면 본문을 유지하고 최신 저장본을 대조한 다음 사용자가 다시 저장하게 한다. 현재 버전으로 자동 덮어쓰거나 외부 저장소에 메모를 올리지 않는다.

설비 이력 조회 화면에서는 저장된 메모의 equipment 배열로 역방향 링크를 표시한다. 설비 식별자가 회사 시스템의 불변 ID라면 표시명 대신 해당 ID를 연결 키로 사용한다. 이름 변경 시 링크 마이그레이션 규칙을 추가해야 한다.

합격 조건: 날짜별 내용 분리, 저장·재조회, 알려진 설비만 연결, 중복 링크 하나, HTML 문자열이 텍스트로 유지, 잘못된 날짜/길이 거절, 충돌 409, 인증 없는 접근 거절. `test/schedule.test.js`를 참고한다.
