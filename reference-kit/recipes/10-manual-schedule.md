# 10. 담당자·날짜·시간 직접 지정과 변경

읽기: `workflows.js`의 scheduleTask, router.js의 POST /schedule, public/reference-lab/app.js의 showSchedule.

입력 `{taskId,personId,day,start,actor}`. 예상 시간은 기존 task.minutes를 사용하므로 브라우저가 임의 길이를 보내도 신뢰하지 않는다. 기존 업무의 earliest/deadline 시각 안이어야 한다. 자정을 넘는 일정은 거절한다.

해당 업무의 기존 예약만 제외한 뒤 planDay에 업무 하나와 선택 담당자만 전달한다. 강제 시작과 종료로 후보 구간을 제한하여 역량·활성 상태·하루 용량·근무/휴게·사람/설비 충돌을 같은 엔진에서 검사한다. 통과한 뒤에만 기존 예약을 교체한다. 이미 기록한 체크리스트와 메모는 보존하며 완료된 작업은 이동하지 않는다. 원천 day와 실제 plannedDay를 구분한다. 운영에서는 날짜 변경이 원천 납기를 넘길 수 있는지 회사 정책을 별도로 적용한다.

일정·업무 상태·체크리스트·이력을 한 트랜잭션으로 저장한다. 버전 충돌은 409, 입력/조건 위반은 400이다. 화면에서 거절 이유를 보여주고 입력을 유지한다. 운영에서 누가 다른 사람의 업무를 이동할 수 있는지 회사의 권한 규칙을 붙인다.

캘린더의 주간·월간·목록 보기와 담당자 필터는 같은 원천을 사용한다. taskId 없는 회의는 읽기 전용으로 표시하되 자동·수동 배정의 점유 시간에 포함한다. 아직 일정 취소·반복 일정·드래그 이동은 구현하지 않았다.

합격 조건: 부적격 담당자 거절, 점심/기존 회의/설비 중복/하루 용량/원천 시간 경계 거절, 오류 시 부분 변경 없음, 직접 확정 시 체크 생성, 이동 시 체크 보존, 완료 업무 이동 거절, 같은 버전 동시 변경 하나만 성공. `test/schedule.test.js`를 참고한다.
