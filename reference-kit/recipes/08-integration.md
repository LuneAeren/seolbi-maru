# 08 · 기존 회사 사이트에 이식하는 순서

1. 현재 화면·로그인·DB를 그대로 유지한다. 새 사이트 전체를 덮어쓰지 않는다.
2. planner.js의 입력/출력과 테스트를 먼저 옮긴다.
3. 회사의 사람·설비·업무·일정 필드를 정규화하는 작은 어댑터를 만든다.
4. 가짜 데이터로 배정만 계산하고 실제 일정에는 쓰지 않는다.
5. 과장급의 확정 권한, 담당자의 체크 권한, 팀 열람 범위를 기존 사내 계정에 연결한다.
6. 일정·체크리스트·인폼·이력을 회사 DB 트랜잭션으로 연결하고 중복 키를 유지한다.
7. 부분 수집·동기화 실패·버전 충돌·시간대·휴게·교대 조건을 검수한다.
8. 선택한 디자인에서 필요한 레이아웃·토큰만 기존 UI에 적용한다.

router.js의 ref:workspace 통합 저장은 설명 가능한 예제다. 기존 DB를 이 스키마로 교체하라는 뜻이 아니다. 운영 모드의 레퍼런스 쓰기는 기본 차단되어 있다. 실제 회사 데이터 연결과 권한 검토가 끝난 기능만 회사 내에서 활성화한다.
