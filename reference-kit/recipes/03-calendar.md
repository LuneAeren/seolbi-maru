# 03 · 배정 초안 → 확정 일정

입구: `previewPlan`, `commitPlan`과 `/plan/preview`, `/plan/commit` API.

미리보기는 저장하지 않는다. 확정 시 서버가 현재 버전의 입력으로 계획을 다시 계산한다. 브라우저가 보낸 담당자·시간 배열을 그대로 신뢰하지 않는다. 버전이 달라졌으면 409로 다시 검토하게 한다.

업무 일정과 체크리스트를 같은 트랜잭션으로 생성하고, task_id로 중복 일정을 방지한다. 기존 회사 일정 API가 별도 시스템이면 ‘DB 저장 → 일정 시스템 전송’을 단순 연속 호출하지 말고 outbox·재시도·중복 키·실패 상태를 설계한다. 외부 회사 시스템 호출 예제는 포함하지 않았다.

원래 예정일은 `day`, 이월 후 확정일은 `plannedDay`로 구분한다. 인수인계 화면은 확정일을 기준으로 잡는다. 예시 시간축은 09~17시이며 실제 교대·야간 근무는 회사 설정에 맞춰 UI와 알고리즘을 함께 확장한다.
