# 사내 에이전트 인계 · Express.js 버전

기준일: 2026-11-15. 실제 시스템 주소, 인증정보, 사용자 명단과 실데이터는 이 저장소에 기록하지 않는다.

## 1. 실행 환경

- Node.js 24.x, Express 5.x. 서버와 브라우저 자산을 한 앱이 제공한다. Streamlit·Python·외부 호스팅은 필요 없다.
- 개발 기본값은 `APP_MODE=demo`, `HOST=127.0.0.1`, `PORT=4317`이다. 데모를 다른 네트워크 주소에 바인딩하면 시작을 거절한다.
- `npm ci --ignore-scripts`로 잠금 파일 그대로 설치한다. 인터넷을 사용할 수 없는 환경은 회사 승인 npm 미러 또는 승인된 캐시를 사용한다. 운영 중 패키지를 다운로드하지 않는다.
- 기본 DB는 데모 `data/demo.sqlite`, 운영 `data/production.sqlite`다. 운영 모드는 데모 자료가 있는 DB 사용을 거절한다.
- 운영 전용 서비스 계정과 로컬 디스크를 사용한다. SQLite DB를 SMB 공유폴더에 두지 않는다. 단일 Node 프로세스 기준이며 여러 서버 인스턴스 사용은 별도 설계한다.
- 파일 원본·전체 표·이력은 DB에 보관한다. OS 파일 권한, 디스크 암호화·용량 제한·백업은 회사 기준을 적용한다.

## 2. 기존 사내 로그인 연결

이 프로젝트는 회사의 실제 SSO를 구현하거나 사내 계정에 접속하지 않았다. 아래는 사내 인증 프록시에서 연결할 수 있는 검증 규약이다. 기존 SSO와 다른 방식이면 `src/security.js`를 회사 승인 방식에 맞춰 교체하고 보안 테스트를 유지한다.

운영 설정에 필요한 값:

| 설정 | 요구사항 |
| --- | --- |
| APP_MODE | production |
| NODE_ENV | production 권장. 이 값이 production이면 demo 모드 시작 불가 |
| PUBLIC_ORIGIN | 브라우저에서 접속하는 사내 HTTPS origin. 경로·마지막 슬래시 제외 |
| AUTH_PROXY_SECRET | 사내에서 생성한 32자 이상의 충분히 무작위인 비밀값 |
| DEPARTMENT_USERS | 허용할 사내 계정 식별자 목록. 쉼표 구분 |
| AUTH_PROXY_IPS | 인증 프록시가 실제로 연결하는 소켓 IP 목록. 클라이언트 헤더 IP를 사용하지 않음 |
| HOST | 프록시와 같은 호스트면 127.0.0.1 유지. 별도 호스트 구성은 방화벽 검토 후 지정 |
| ALLOWED_SITE_HOSTS | 허용된 사내 업무사이트의 정확한 host[:port] 목록 |
| STALE_AFTER_MINUTES | 업무에서 합의한 데이터 기준 경과 시간. 초기 예시는 30분 |

프록시는 사내 계정 인증과 부서 권한을 먼저 확인한 뒤, 클라이언트가 보낸 `X-Portal-*` 헤더를 제거하고 매 요청에 아래 값을 새로 만든다.

- `X-Portal-User`: 인증된 사내 계정 식별자
- `X-Portal-Time`: 밀리초 단위 현재 시각, 13자리 정수
- `X-Portal-Signature`: 아래 UTF-8 문자열을 AUTH_PROXY_SECRET으로 HMAC-SHA256한 소문자 hex

```text
사용자식별자\n타임스탬프\n대문자HTTP메서드\n원래요청경로와쿼리
```

`\n`은 실제 줄바꿈이며 마지막에는 줄바꿈을 추가하지 않는다. 프록시와 앱 사이에서 경로·쿼리가 바뀌면 서명이 일치하지 않으므로 앱이 실제 수신하는 originalUrl 기준으로 서명한다. 인증·시각 검증은 모든 화면·자산·API 요청에 적용되며 `/health`만 상태 확인용으로 열려 있다.

- 앱은 실제 프록시 IP, 부서 계정 목록, ±30초 시각, HMAC을 모두 검사한다. 시각 동기화를 확인한다.
- 앱이 만든 HttpOnly·SameSite=Strict 세션 쿠키와 요청 토큰으로 쓰기 요청을 검증한다. 운영 쿠키는 Secure다.
- 서명 헤더가 없는 직접 접근, 임의 사용자명, 원본 서명과 다른 요청 경로는 인증으로 인정하지 않는다.
- 운영 설정이 빠지면 실행을 거절하며, 인증 실패 시 데모 계정으로 돌아가지 않는다.
- 앱의 직접 포트 접근은 회사 방화벽으로 프록시에만 허용한다. HTTPS·헤더 제거·인증 프록시 설정은 사내 검수 대상이다.

## 3. Hue·Splunk 연결

`src/connectors.js`는 비활성 계약만 제공하며 어떤 주소도 호출하지 않는다. 사내에서 기존 승인 경로·권한·쿼리·페이지 처리·검색 작업 완료 기준을 확인하고 조회 어댑터를 작성한다. 보안 차단을 우회하거나 브라우저 로그인 쿠키를 추출하지 않는다.

정규화된 결과를 `src/ingestion.js`의 `applySnapshot(store, source, snapshot, actor)`에 전달한다.

```js
{
  complete: true,
  readCount: 1,
  rejectedCount: 0,
  observedAt: '2026-11-15T00:00:00.000Z',
  records: [{
    sourceId: 'FAKE-001',
    title: '가짜 설비',
    area: '예시 구역',
    status: '운전',
    observedAt: '2026-11-15T00:00:00.000Z',
    summary: ''
  }]
}
```

- 위 값은 가짜 예시다. source는 hue 또는 splunk다.
- 상태는 운전·정지·점검·확인불가로 매핑한다. 새 상태 체계는 서버와 화면을 함께 변경하고 검사한다.
- 원천 키는 영문·숫자·밑줄·하이픈을 사용한다. 회사의 실제 키 형식이 다르면 충돌 없는 매핑을 내부에서 정의한다.
- 전체 수집 완료 여부를 확인할 수 없는 결과, 거절한 행이 있는 결과, 중복 키, 잘못된 자료형, 빈 스냅샷은 기존 정상본을 교체하지 않는다. 빈 전체가 정상인 업무는 별도 검토 후 구현한다.
- 통과한 스냅샷은 단일 SQLite 트랜잭션으로 반영한다. 이전 버전과 원천 상태를 보관하고 누락된 이전 설비는 삭제 상태로 남긴다.
- 수집 실패 시 마지막 정상본을 유지하고 출처에 갱신 실패를 표시한다. 쿼리 실행 실패도 호출자가 실패 상태에 기록하도록 어댑터에 구현해야 한다.
- 원천 설비는 포털에서 상태를 덮어쓰거나 삭제·복구하지 못한다. 수동 보정 사항은 연결 설비의 작업 메모에 작성한다. 원천 DB에는 쓰지 않는다.
- 같은 물리 설비가 Hue와 Splunk에 모두 나타나는 경우 현재 키는 `source:sourceId`로 분리된다. 실제 운영 전 기준 설비 목록과 중복 제거·우선순위를 정해 단일 원천 연결부로 정규화한다.
- 자동 실행 주기·스케줄러는 회사에서 정한다. 현재 앱에는 원천 시스템을 호출하는 타이머가 없다.

## 4. 파일 처리와 한계

- CSV: UTF-8 또는 CP949/EUC-KR을 사용자가 선택한다. 자동 추측으로 글자가 바뀌는 것을 피한다.
- XLSX: 시트 선택과 열 이름 매핑, 수식을 실행하지 않는 텍스트 반입. 원본의 모든 서식·수식 계산·차트 보존은 제공하지 않는다.
- 입력 최대 5MB, 30,000행, 50열, 전체 500,000셀, 셀당 8,000자. 시트 최대 10개, ZIP 항목 최대 600개, 전체 압축 해제 32MB·단일 항목 16MB·압축비 250배 제한.
- 파일 파싱은 별도 worker에서 12초 제한·192MB V8 old-generation 제한을 적용한다. worker 전체 프로세스 RSS 제한이나 OS 격리를 대신하지 않는다. 파일 처리 동시 최대 2개다.
- 반입 미리보기는 10분 동안 유효하고 최대 8개·원본 합계 20MB로 제한한다. 재시작 시 미리보기는 사라지고 저장된 자료는 유지된다.
- 표는 50행씩 조회한다. 한 번에 500개 셀을 수정·출력할 수 있다. 현재 버전은 행 추가·삭제·열 자료형 설정 UI를 제공하지 않는다.
- CSV 다운로드는 수식 위험 문자열에 작은따옴표를 붙일 수 있다. 정확한 원문 보존이 필요하면 XLSX 문자열 출력을 사용하거나 보존된 원본을 다운로드한다.
- 원본 다운로드는 인증된 사용자에게 attachment로 제공한다. 자체 악성코드 엔진은 없으므로 반입 전 회사의 승인된 검사 절차를 적용한다. 외부 검사 사이트로 전송하지 않는다.
- 현재 PDF 반입·표 추출·편집은 제공하지 않는다.

## 5. 배포 전 검수

1. 회사가 승인한 Node·패키지 버전과 잠금 파일을 검사하고 `npm test`, `npm run check`를 실행한다.
2. 사내 프록시·HTTPS·SSO·계정 허용 목록·서명 검증을 확인한다. 인증 실패·프록시 우회·다른 부서 계정을 검사한다.
3. 운영 계정으로 CSV·XLSX 업로드, 편집, 미저장 출력, 공유 저장, 충돌, 이력·복구와 원본 다운로드를 확인한다.
4. Windows·실제 Edge 버전에서 한글·날짜·앞자리 0과 파일 처리를 확인한다. 외부 개발 검수는 macOS의 앱 내 브라우저에서 수행했다.
5. 20명의 실제 사용 패턴과 사내 서버 사양으로 응답·메모리·디스크·장시간 사용을 측정한다. 현재 테스트의 동시 저장 20건은 20명 장시간 부하 검증이 아니다.
6. 원천 연결 실패·부분 수집·기준 경과 시 정상 수치로 오인하지 않는지 확인한다.
7. 브라우저와 서버 양쪽에서 외부 통신이 차단되는지 회사 도구로 검사한다. 앱은 외부 호출 코드를 포함하지 않지만 OS·브라우저·의존성 전체의 무통신을 보증하지 않는다.
8. 실행 중 SQLite 파일만 복사하지 않는다. 앱을 정지한 뒤 DB 및 남아 있는 WAL 관련 파일을 함께 보관하거나 회사가 검증한 SQLite 백업 절차를 사용한다. 복구는 별도 테스트 DB에서 확인한다.
9. 보존할 이력·원본의 기간과 용량을 정한다. 현재 모든 버전이 보관되고 화면에는 최근 100개까지 표시된다. 용량 정리 정책은 구현되지 않았다.
10. 현재 운영본·설정·DB 백업과 복구 절차를 확인한 뒤 사내 승인 절차에 따라 반영한다.
