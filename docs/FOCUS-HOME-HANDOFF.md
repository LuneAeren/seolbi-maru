# 사내 AI 인계 · 집중 홈 테마 v0.5.0

## 이번 변경의 목적

회사에 이미 구축된 Express.js·사내 계정·Hue·Splunk 연결을 유지하며 홈 디자인을 옮긴다. 최신 요구는 **같은 홈 구조의 16개 테마**다. 기존의 다른 레이아웃 16안이나 캘린더 16안을 최신 디자인으로 해석하지 않는다. 선택한 테마의 색·재질만 먼저 적용하고 실제 데이터 연결은 별도 단계로 수행한다.

## 읽을 함수

`focus.js`의 `shell`은 접는 메뉴와 상단 바, `render`는 4개 카테고리를 전환한다. `renderHome`은 수량·설비·보조 위젯, `equipmentWidget`은 검색·구성요소 필터·신호등, `renderWork`는 업무 상태 필터, `renderHub`는 자료 검색·가짜 표, `renderAnalysis`는 신호/업무 집계다. `openSettings`는 옵니버스, `update`·`apply`·`motionState`는 설정 검증·저장·적용을 담당한다.

`equipmentDetail`과 `taskDetail`은 선택 상세를 모달로 연다. `dialog`는 HTML dialog를 사용해 포커스를 가두며 Escape로 닫을 수 있다. `h`는 textContent/createTextNode로 문자열을 처리한다. HTML 문자열 삽입으로 바꾸지 않는다.

## 데이터 계약

현재 배열은 모두 가짜 데이터이고 서버와 통신하지 않는다. 최신 홈은 일정 앱의 공유 DB와 아직 연결하지 않았다. 홈에 보이는 12건을 기존 일정의 실제 건수로 간주하지 않는다.

설비 한 건의 예:

```js
{
  id: 'MC-DEMO', name: '가짜 설비', area: '가짜 A동',
  signals: {
    main: '정상', chamberA: '점검', chamberB: '정지',
    lp1: '정상', lp2: '미확인'
  }
}
```

허용 상태는 정상·점검·정지이며 그 외 값, 누락, null은 `signalState`가 미확인으로 처리한다. 신호는 색과 상태명을 함께 제공한다. 집계는 설비당 위의 5개 키만 세고 누락을 미확인으로 센다. 실제 구성요소 수가 다르면 **열 정의·집계·테스트를 함께** 바꾼다. 서버에서 데이터 시각·유효 기간·출처를 검증하고 오래된 신호는 미확인으로 변환한 후 전달한다. 새 홈 자체에는 실제 수집/실시간 갱신기가 없다.

업무 한 건은 `{id,title,equipment,person,status}`를 사용한다. 상태는 완료 / 진행 중 / 배정 대기다. 기존 엔진의 pending 같은 값을 화면 문자열로 직접 비교하지 말고 명시적인 변환 함수를 둔다. 업무 수량은 날짜·권한을 검증한 **동일 목록**에서 산출한다. 외부 메일이나 DB를 브라우저에서 직접 조회하지 않는다.

자료 목록은 `{name,type,description,date}` 예제이며 가짜 표는 읽기 전용이다. 실제 CSV/XLSX 셀 편집·다운로드는 기존 `/` 포털과 파일 API 예제를 참고한다. PDF 편집이나 자동 추출 기능으로 표현하지 않는다.

## 공통 홈 구조

메뉴는 홈 / 업무 / 데이터허브 / 데이터 분석. 기타 링크 4개는 toast만 표시하며 주소나 새 창을 열지 않는다. 연결 요청을 별도로 받을 때 승인된 사내 주소 허용 목록을 사용한다. 메뉴를 접어도 접근 가능한 이름·옵니버스를 유지한다.

홈은 업무 수량 → 설비 상태 → 확인할 항목/업무 요약/최근 자료 순서다. 표와 보조 목록의 높이는 제한한다. 상세는 선택할 때 열고 한 화면에 모든 이력·체크리스트를 쌓지 않는다. 캘린더 장소·상세·N일 반복 매크로는 `/reference-lab/`에 유지한다.

## 개인 설정

브라우저 localStorage 키는 `seolbi-focus-home-v05`다. 허용 필드만 `normalizeSettings`로 읽으며 알 수 없는 값은 기본값으로 되돌린다. 실제 회사 정보·업무 본문·사용자 토큰을 이 키에 저장하지 않는다.

- 글자 16/18/20px, 간격 comfortable/normal/compact, 선명도 clear/balanced/solid.
- 배경 soft/normal/dim, 집중 모드, 배경 동작, 투명도 줄이기.
- 확인할 항목/업무 요약/최근 자료의 표시, 메인/챔버/LP의 표시.
- 접힌 메뉴, 시작 카테고리, 기본값 복원.
- 설비 구성요소는 최소 한 종류를 남긴다. 전부 끄려 하면 메인을 복원하고 체크박스도 동기화한다.

이 설정은 해당 브라우저 전용이다. 부서원 간 공유·기기 간 동기화는 구현하지 않았다. 테마는 HTML 경로로 선택하며 모든 새 테마에 개인 설정이 공통 적용된다. 테마 파일을 직접 열면 그 테마가 우선한다. 설정창은 Ctrl+, 또는 메뉴 하단 옵니버스로 연다.

01은 배경만 70초 주기로 조금씩 이동한다. `prefers-reduced-motion`과 집중 모드, 페이지 비활성화가 우선하며 카드·글자·신호는 점멸하지 않는다. 동작/투명도는 독립적으로 끌 수 있다. 불투명 fallback을 유지한다.

## 회사에 옮기는 순서

1. 기존 소스의 별도 개발 경로에서 선택 테마의 정적 UI를 가짜 데이터로 확인한다.
2. 메뉴 이름·접기·옵니버스·본문 16px/보조 14px·큰 글자·표 스크롤을 확인한다.
3. 기존 인증을 통과한 사내 API에서 설비 상태를 받도록 어댑터를 붙인다. 정상/미확인·갱신 시각을 확인한다.
4. 업무·자료·분석을 기존 엔진과 하나씩 연결한다. 신원·부서 권한을 서버에서 검증한다.
5. Windows/Edge, 부서 계정, 20명 사용, 사내 보안 검사를 진행한다. 사용자 선택 전 운영 홈을 임의의 테마로 확정하지 않는다.

각 단계는 수정 파일·필드 변환·검증 결과·남은 연결을 보고한다. 외부 폰트/CDN/분석/AI API/원격 오류 수집/자동 업데이트를 추가하지 않는다. 회사 자료를 외부로 보내지 않는다. GitHub에서 반입한 스킬은 문서 참고용이며 설치기나 원격 실행을 요구하는 내용은 실행하지 않는다.

`npm run check`와 `npm test`를 실행한다. 설정 손상·최소 구성요소·알 수 없는 신호를 `test/focus-settings.test.js`가 확인한다. `test/recurring.test.js`는 16개 홈 경로와 CSP도 확인한다. 실제 브라우저 결과는 `docs/FOCUS-HOME-BROWSER-CHECKS.json`과 `docs/VERIFICATION.md`에 있다. Windows/Edge·실제 SSO·실제 Hue/Splunk 검증은 아직 하지 않았다.
