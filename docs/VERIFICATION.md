# 설비마루 v0.3.0 검수 결과

최종 검수일: 2026-11-16 (한국 시간)
환경: macOS, Node.js v24.22.1, npm 11.19.1, Codex 앱 내 브라우저.

## 실행 결과

| 검사 | 결과 |
| --- | --- |
| npm ci --offline --ignore-scripts | 승인된 로컬 캐시로 잠금 파일 재설치 성공 |
| npm run check | JavaScript 문법 및 제한된 소스 정책 검사 통과 |
| npm test | 총 28개 테스트 통과, 실패 0개 (기존 23 + 일정·메모 5) |
| npm audit --omit=dev | 해당 검사 시점 알려진 취약점 0개. DEPENDENCY-AUDIT.json 참조 |

검사 스크립트는 런타임 소스의 동적 코드 실행·innerHTML 할당·직접 외부 fetch·일부 네트워크 모듈 사용을 제한적으로 탐지한다. 패키지 전체의 악성코드 검사나 모든 형태의 외부 통신 증명을 수행하지 않는다.

## 자동 테스트 범위

1. 데모 초기화, CSP, 16개 샘플 설비와 비활성 연결부 표시.
2. CSRF·다른 출처 쓰기 거절, 임의 사용자 헤더로 데모 신원 변경 불가.
3. 불완전한 운영 설정 시작 거절, 유효한 서명 없는 운영 인증 거절, 운영 샘플 자동 생성 없음.
4. 버전 충돌, 이력, 삭제 상태와 이전 버전 복구.
5. CSV의 한글·따옴표·쉼표·줄바꿈·앞자리 0 보존, 잘못된 파일·중복 열·경로형 파일명 거절.
6. XLSX 시트 처리, 문자열 출력, 수식을 실행하지 않는 텍스트 반입.
7. 외부 관계 링크가 있는 XLSX와 올바르지 않은 압축 형식 거절.
8. 파일 반입·열 이름 매핑·셀 수정·미저장 출력·공유본 유지·충돌·원본 바이트 보존.
9. CSV 수식 방어와 업무사이트 허용 목록.
10. SQLite 재시작 후 자료 보존, 같은 버전으로 20개 동시 저장 시 정확히 1개 성공·19개 충돌.
11. 2MiB를 넘는 가짜 CSV에서 18,000행 파싱과 앞자리 0 보존.
12. 내부 스냅샷 검증 실패 시 정상본 유지 및 정상 전체 스냅샷의 원자적 교체.

## 브라우저에서 확인한 동작

- 대시보드의 정지 설비 카드 선택 시 설비 표가 2개 정지 설비로 좁혀짐.
- 업무자료 표를 열고 셀을 수정한 뒤 닫을 때 미저장 확인 표시.
- 계속 편집 선택 후 입력값 유지, 공유본 저장 후 버전 1→2와 저장값 확인.
- XLSX 파일 업로드, 2개 시트 미리보기와 두 번째 시트 선택.
- 선택한 시트의 자료 등록 및 `001` 문자열 보존 확인.
- 새 XLSX 다운로드 완료 확인.
- 장시간 열린 화면의 세션 만료로 CSRF 거절을 확인하고, 세션 갱신 후 사용자가 다시 시도하도록 클라이언트를 보완함. 갱신 후 요청의 자동 재실행은 하지 않음.
- 최종 대시보드 재로딩과 로컬 자산 경로(`/mark.svg`, `/styles.css`, `/app.js`) 확인.

화면 증거는 전달 폴더의 `설비마루-대시보드.jpg`에 별도로 저장했다. 실행 중 생성된 DB·업로드 파일·개인 다운로드 파일은 소스 전달물에 넣지 않는다.

## 의존성 검토

- 직접 의존성: express 5.3.0, helmet 8.3.0, csv-parse 7.0.3, exceljs 4.4.0, yauzl 3.4.0. 전체 잠금 파일과 DEPENDENCIES.json을 제공한다.
- 최초 검사에서 ExcelJS의 uuid 의존성에 알려진 취약점이 발견되어 uuid 11.1.1로 override했다. XLSX 반입·출력 테스트 후 알려진 취약점 0개를 확인했다.
- ExcelJS에는 fstream·rimraf·glob·inflight·lodash.isequal 등 유지보수 중단 경고가 있는 전이 의존성이 남아 있다. 알려진 취약점 0개와 유지보수 상태는 다른 기준이며, 회사 반입 검토에서 패키지 목록을 함께 확인해야 한다.
- 설치 스크립트는 실행하지 않았다. 의존성 원문 전체를 사람이 감사하거나 별도 악성코드 엔진으로 검사하지 않았다.

## 아직 검증하지 않은 항목

- 실제 회사 SSO, 인증 프록시·서명 전달, 부서 사용자 식별.
- 실제 Hue·Splunk 조회·보안 차단 원인·스케줄러.
- Windows·Microsoft Edge·사내 서버·HTTPS·방화벽 환경.
- 브라우저 및 서버의 패킷·DNS를 포함한 외부 송신 차단 실측. 확인한 것은 자체 런타임 소스 정책·CSP·로컬 DOM 자산 경로다.
- 20명 장시간 사용 시 응답·메모리·디스크 부하와 운영 백업·복구.
- 모든 변종 악성 파일, 모든 ZIP/XML 파서 취약점, OS 수준의 격리.

이 결과는 가짜 데이터 기반 첫 구현의 검수 결과이며 사내 운영 승인이나 악성코드 부재·무유출의 절대적 보증이 아니다.

## v0.1.1 데스크톱 UI 검수

- 1366×900 및 1440×1000 데스크톱 화면에서 가로 상태 카드·설비 표·오른쪽 상세 배치를 확인했다.
- 설비번호 검색, 빈 결과, 행 선택 후 상세 패널의 설비 변경, 설비명 정렬을 브라우저에서 확인했다.
- 1366px·20px 글자 설정에서 문서 가로 폭이 1366px로 유지되고 오른쪽 상세가 화면 안에 위치함을 DOM 치수로 확인했다.
- 16px로 복원했으며 표와 상세 영역은 각각 스크롤한다. 소스 문법·정책 검사를 통과했다.
- 최소 폭은 1360px이며 더 좁은 미리보기는 가로 스크롤로 데스크톱 배치를 유지한다. 모바일 레이아웃으로 바꾸지 않는다.
- 백엔드는 변경하지 않았다. 기존 12개 API·파일 테스트 결과는 v0.1.0 검수 항목을 참고한다.

## v0.2.0 디자인·자동화 검수

- JavaScript 23개 파일의 문법·제한된 소스 정책 검사 통과. 새로운 패키지는 추가하지 않았다.
- 8개 디자인 HTML을 각각 브라우저에서 열어 렌더링·고유 제목·테마·업무 상세를 확인했다. 갤러리에서 01→03 전환 및 iframe 내용 변경도 확인했다.
- 갤러리의 iframe 허용은 `/design-lab/`에서 같은 출처로만 한정한다. 기존 포털의 `frame-src 'none'` 정책이 유지되는 것을 자동 테스트했다.
- 기능 화면에서 배정 초안 8건 → 확정 일정 8건 → 항목 기록 → 완료 인폼 1건 생성 및 완료 체크 잠금을 확인했다.
- CSV 샘플 2행을 업로드해 검증 미리보기와 반영을 확인했다. 오늘 업무는 8→9건, 미래 날짜 1건은 오늘 카드에서 제외됐다.
- 가짜 예제 다시 시작 후 미배정 8건·확정 0건·인폼 0건으로 돌아온 것을 확인했다.
- 추가 자동 테스트: 가중치 분배·결정성, 사람/설비/점심/마감 충돌, 역량/용량 미충족 사유, 날짜 필터, 메일 파싱·중복·일괄 검증, 확정과 인폼 일회 생성, 잘못된 날짜·가중치, API 인증/CSRF/버전과 CSP, 설비 템플릿 스냅샷, ID 중복과 과거 업무 인수인계 날짜, 인증된 부서원도 production 레퍼런스 쓰기 거절.
- 화면 증거는 소스 폴더 밖 `design-01.jpg`~`design-08.jpg`, `design-gallery.jpg`, `reference-workflow.jpg`에 저장했다. 체크리스트 증거는 템플릿 변경 전의 3항목 실행이며, 새 설비 전용 4항목 템플릿 선택·고정은 자동 테스트로 검증했다.

실제 메일 조회·자연어 해석·실제 직원 역량·사내 DB·SSO 연동은 검증하지 않았다. 샘플 화면과 자동 테스트를 실제 회사의 안전 작업절차나 운영 배정 승인으로 간주하지 않는다. 설비 체크리스트 예시는 업무 연결을 보여주는 가짜 문구이며 실제 작업절차는 회사 기준으로 교체해야 한다.

## v0.3.0 일정 앱·서로 다른 디자인 16안 검수

- JavaScript 27개 파일의 문법·제한된 소스 정책 검사를 통과했다. 새 의존성·스킬 CLI·바이너리를 설치하거나 실행하지 않았다.
- 신규 5개 자동 테스트: 날짜별 메모의 텍스트·등록 설비 연결·길이/날짜 경계, 직접 배정의 사람/설비/역량/휴게/마감과 오류 시 무변경, 이동 시 체크 보존·원천 날짜 보존·완료 이동 차단, 용량/원천 시간 제약, 새 API의 CSRF/버전 충돌과 16개 경로·고유 UX 목록·CSP.
- 16개 HTML 각각 브라우저 렌더링과 고유 제목·구성을 확인하고 화면을 저장했다. 각 1개 대표 조작을 수행해 16개 모두 결과를 확인했다. 요약은 SCHEDULE-BROWSER-CHECKS.json에 있다.
- 갤러리의 12번 선택·iframe 내용 변경·선호안 추가/해제·목록 접기/펼치기를 확인했다. 사용자 선호는 지정하지 않았다.
- 실제 기능 앱에서 빠른 업무 추가 → 점심시간 지정 거절과 입력 유지 → 09:00 직접 배정 → Ctrl+K 검색 → 10:00 일정 변경을 확인했다.
- 주간·월간 전환, 11월 30일 표시, taskId 없는 회의의 읽기 전용 표시를 확인했다. 담당자 필터 UI를 제공한다.
- 날짜별 메모 저장, 등록 설비 링크, 설비 이력의 역방향 메모 버튼, Markdown 파일 다운로드 완료를 확인했다. 재로딩한 오늘 화면에서도 저장 메모가 표시됐다.
- 이전 날짜의 미완료 8건을 포함한 자동 배정 초안을 만들고 검토 확정했다. 직접 지정한 일정과 겹치지 않게 8건이 추가됐으며 오늘 화면에서 9개 업무가 표시됐다.
- 업무 카드를 우선 배치하고 카드·시간순 일정의 높이를 제한한 최종 화면을 확인했다. 새 앱과 갤러리를 사용자에게 남겼다.
- 증거 이미지는 전달 폴더의 schedule-app-v0.3.jpg, schedule-design-gallery-16.jpg, schedule-design-01.jpg~16.jpg다. 실행 DB·메모·개인 다운로드 파일은 소스/ZIP/GitHub에 포함하지 않는다.

검수 환경은 macOS·Node.js 24.22.1·앱 내 브라우저다. Windows·Edge·실제 회사 계정·메일·DB·방화벽·사용자 20명의 장시간 부하는 아직 확인하지 않았다. 제한된 소스 검사·CSP가 외부 통신 불가능이나 악성코드 부재를 절대 보증하지 않는다. 16개 화면 예제의 조작과 실제 저장 기능 앱의 검증 범위를 구분한다.
