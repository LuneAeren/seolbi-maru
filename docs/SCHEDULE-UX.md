# 이전 일정 워크스페이스 UX 명세 · v0.3.0

현재 홈화면 디자인 대상은 `docs/HOME-DESIGN-BRIEF.md`와 `/home-designs/`의 16안이다. 이 문서는 이전 일정 화면의 설계 기록이다. v0.4.0 장소·상세·반복 생성은 `reference-kit/recipes/11-calendar-details-recurring.md`를 따른다.

대상은 PC·Windows·Edge를 사용하는 설비 엔지니어 부서 약 20명이다. 실제 회사에 구축된 사이트의 일정·체크·인폼·이력을 유지하면서 필요한 화면과 서비스 함수를 옮긴다. 회사 운영 환경 검증은 아직 수행하지 않았다.

## 문제와 변경

기존에는 배정·일정·작업·이력이 한 화면에 많이 나타나 맥락을 찾기 어려웠다. 이번 첫 화면은 업무 카드, 짧은 시간순 일정, 날짜별 메모로 한정한다. 자동 배정 검토, 작업 상세, 설비 이력, 설정은 별도 화면에서 연다.

- 오늘 업무 카드를 주 영역으로 두고 카드 영역 안에서 스크롤·검색·상태 필터를 제공한다.
- 오른쪽 시간순 일정과 메모는 높이를 제한한다. 글자를 줄여 데이터를 끼워 넣지 않는다.
- 업무 추가는 3개 주요 입력과 설명된 기본값을 사용한다. 고급 옵션은 details 요소로 펼친다.
- 자동 배정은 초안 → 이유·미배정 검토 → 명시적 확정이다. 직접 지정·이동도 같은 배정 규칙으로 검증한다.
- 날짜를 바꾸면 오늘·메모·캘린더의 맥락이 이어진다. 실행일과 원천 날짜를 구분한다.
- 주간·월간·목록 보기는 같은 자료를 사용한다. 미배정은 시각 대신 '미배정', 회의는 '읽기 전용'으로 표시한다.
- 선택한 업무의 체크리스트와 인폼만 연다. 이력은 설비를 기준으로 조회한다.
- 날짜 메모의 `[[설비명]]`과 설비 이력의 관련 메모를 연결한다. 외부 링크로 확장하지 않는다.

## 처음 사용하는 사람의 흐름

1. 오늘 화면에서 '+ 업무 추가' 또는 업무함의 메일·파일 반입을 선택한다.
2. 업무를 추가한 후 자동 배정 검토 또는 카드의 일정 지정을 선택한다.
3. 역량·근무·휴게·일정 충돌을 확인하고 일정을 확정한다.
4. 일정에서 작업 열기로 체크리스트에 접근하고 항목별 기록 후 완료한다.
5. 일일 메모에 이어갈 내용과 설비를 적고 저장한다. 필요하면 인수인계 요약·Markdown을 출력한다.

처음 사용 안내와 모든 작업 버튼을 제공한다. 단축키를 알아야만 사용할 수 있는 기능은 없다. Ctrl+K 검색과 N 빠른 추가는 보조 수단이다. 입력 중 N은 단축키로 처리하지 않는다.

## 16개 디자인 레퍼런스의 차이

`public/schedule-designs/catalog.js`가 번호·이름·구조·체험 흐름의 단일 목록이다. `prototypes.js`에는 16개 별도 구성 함수가 있고 HTML마다 고유 data-concept로 선택한다. 데이터와 작은 UI 요소만 공유한다.

| --- | --- | --- | --- |
| 01 Vault | 파일 트리·날짜 | 문서·백링크 | 날짜 문서 전환 |

| 04 Matrix | 담당자 행 | 사람 × 요일 표 | 동일 담당자 다음 작업 |
| 05 Flow | 진행 상태 열 | 칸반 카드 | 다음 상태로 이동 |

| 09 Month | 월간 날짜 | 달력·상세 서랍 | 30일 포함 날짜 전환 |

단순 색상·글꼴 교체로 16안을 세지 않는다. 프로토타입은 화면 선택용이며 데이터는 가짜, 체크·이동·가중치 조작은 해당 페이지에서만 적용된다. 실제 저장·보안·배정 엔진은 `/reference-lab/`에 있다. 특히 16번은 가중치 비율의 시각화이고 실제 적격 배정이 아니다. 02·08의 시간 표현은 시작 시간대 중심의 시각적 예시이며 운영 시간 배치는 실제 기능 앱의 예약 값을 사용해야 한다.

이전 8개 포털 디자인은 `/design-lab/`에 남겨두었다. 새 16개와 번호를 혼동하지 않도록 '새 일정 16안'으로 표시한다.

## 접근성과 오류 처리

- 본문·입력 기본 16px, 보조 정보 최소 14px. PC 최소 폭은 실제 기능 앱 1300px, 디자인 예제 1280px이다. 좁은 미리보기에서는 가로 이동한다.
- 네이티브 form, label, button, details, dialog와 보이는 포커스를 사용한다. 모달은 Escape 또는 닫기 버튼으로 닫을 수 있다.
- 새 업무/일정 저장 오류는 모달 안에 표시하고 값을 유지한다. 저장 중 중복 요청은 busy 상태로 거절한다.
- 메모는 저장 전 초안을 표시하고 같은 페이지 내 날짜·탭 이동 중 유지한다. 새로고침·종료 전 기본 브라우저 경고를 사용한다. 브라우저 종료 후 미저장 초안 복구는 미구현이다.
- 충돌 시 자동 덮어쓰기·자동 재실행하지 않는다. 최신 서버 버전을 확인하고 재검토한다.
- 외부 자산, 폰트, 분석, AI 호출을 사용하지 않는다. iframe은 디자인 갤러리 경로의 같은 출처에만 허용한다.

## 구현 한계

반복 일정·알림 발송·일정 취소·드래그 이동·야간 교대·여러 명 동시 투입·작업 의존성·휴가 규칙은 미구현이다. 메모는 Markdown 파일로 내보낼 수 있지만 HTML/Markdown 렌더링·Obsidian vault 동기화는 하지 않는다. 실제 메일·DB·인증 연결과 직급별 권한은 사내 연결 작업으로 남아 있다.
